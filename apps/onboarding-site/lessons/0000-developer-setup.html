Run Atlas locally

Install the tools, start the product, and choose whether to reset or keep your local data.

1. Install

You need Git, Docker Desktop with Compose v2, and Node 24.19.0.

npm install --global pnpm@11.19.0
git clone https://github.com/jash33/Atlas-public.git
cd Atlas-public
pnpm install --frozen-lockfile
pnpm setup:local

pnpm check
pnpm typecheck
pnpm build

2. Start Atlas

CommandUse it to
pnpm prepare-demoDelete old local Atlas state and start with an empty capability catalog and no connected repositories.
pnpm infra:upStart the full product. It merges the named provider fixtures and preserves other resources and canonical saved data.
pnpm devRun source code in watch mode. Start its databases and services separately.
pnpm infra:test:e2eRun the full local integration check from a replaced, clean provider baseline.
Normal infra:up is additive for the mock provider: a payment you seed by hand survives another startup. Use prepare-demo only when you want the destructive full-demo reset; infra:test:e2e also replaces provider resources for a repeatable integration check.
Burger Town is a separate demo app still being built, with port 43123 reserved for it. Atlas reaches it from Docker at http://host.docker.internal:43123; the matching browser address is http://localhost:43123. The Burger Town Connect Source form loads these editable addresses from the Backend.
If you ran an earlier blast-radius branch with the old Burger Town migration numbers, recreate the disposable local database before starting this version.
After pulling the Production rename, the first pnpm infra:up may find a retired Production-like Atlas stack. It announces the change, deletes that disposable Atlas project's PostgreSQL, Temporal, and Worker-secret data, then recreates Development and Production. Unrelated Docker resources are excluded. Later starts preserve canonical data. Back up anything valuable outside these demo volumes first.
pnpm dev --console-only starts the Console with Vite hot reload. Compose does not run the Console; port 5173 must be free before starting it.

4. Choose demo services

By default, Stripe, Slack, and HubSpot run as local copies and need no credentials. To use official test accounts, add the providers you want to the root .env:

STRIPE_DEMO_MODE=official-test
STRIPE_SECRET_KEY=sk_test_...

SLACK_DEMO_MODE=official-test
SLACK_BOT_TOKEN=xoxb-...

HUBSPOT_DEMO_MODE=official-test
HUBSPOT_ACCESS_TOKEN=...

A provider set to official-test will not start without its credential.

5. Enable AI drafting (optional)

Running workflows does not need an AI model. Creating a workflow from English does. Save the API key in .local/openai-api-key, then add:

OPENAI_API_KEY_FILE=../../.local/openai-api-key
OPENAI_MODEL=<configured-model>

The key is mounted only in the Backend. Do not paste it into the Console.

6. Reset the demo

pnpm prepare-demo

Open the printed Console link. There are no connected repositories, capabilities, or approved workflows. Connect a service or public repository, review its capabilities, then create, check, approve, and activate a workflow. Its Invoke via API details provide the name and required input fields. Use ATLAS_INGEST_CALLER_TOKEN from your private .env file; there is no shared caller token.

Run tests

Once pnpm infra:up has started PostgreSQL, run pnpm test. It loads the generated test-database connection from .env. Run pnpm typecheck first to build shared packages. Commands using pnpm exec vp use the workspace installation; no global Vite+ installation is needed. In PowerShell, use pnpm.cmd if script execution is disabled.

Focused commands and cleanup

pnpm dev --console-only
pnpm exec vp run @atlas/backend#dev
pnpm exec vp run @atlas/mock-services#dev
pnpm exec vp run @atlas/worker#dev

pnpm infra:down
pnpm infra:clean:docker-cache
pnpm infra:clean:docker-cache -- --include-recent

infra:down keeps saved data. The default cleanup removes dangling Atlas images and build cache older than 24 hours, not containers or volumes. --include-recent removes the cache age cutoff.
