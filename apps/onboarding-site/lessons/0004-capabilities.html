Atlas Console · Lesson 4 · 3 min

Capabilities

A capability is one API action Atlas may use, such as “get an invoice” or “send a message.”

Connect an API

Add an OpenAPI JSON document. Atlas reads it and lists the actions it finds. The page records the import as a confirmed source.

Paste the spec or choose a JSON file. Atlas lists each operation as a capability.

The Burger Town demo has its own connection option. It checks the prepared application and OpenAPI addresses, adds the expected actions and workflow connections, and leaves polling stopped.

Review an action

Select an action to see:

  • the data it accepts and returns;
  • where its definition came from;
  • whether it is current and approved;
  • which credential and host it needs; and
  • which workflows use it.

Approve it

An Admin must confirm safety details before Atlas can use an action in a new workflow. This includes whether retrying is safe and whether the action can be undone. Atlas never guesses these facts.

When an API changes

Atlas saves a new version of the affected action. Existing workflows still point to the version they were approved with. Open Changes to see what needs attention.

When sources disagree

If two connected sources claim different current contracts for the same action, the catalog marks it Conflicting sources and keeps it out of new workflow plans. Its details drawer shows every candidate version and where it came from. An Admin can designate one source as authoritative for the selected environment, or clear that choice after correcting the registrations.
